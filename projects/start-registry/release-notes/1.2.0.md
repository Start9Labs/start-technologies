**start-registry 1.2.0 serves package icons from a cacheable content-addressed store, labels signatures with their actual scheme, and picks up security fixes in its dependencies.**

## Highlights

- **Package icons are served from `/icons/`** and stored once by content hash, however many package versions and dependents use them. StartOS 0.4.0.3 and later fetch them on demand; earlier versions still receive icons inline.
- **Signatures carry their actual scheme.** Ed25519ph signatures get their own algorithm label, and `id-Ed25519` now marks only pure Ed25519 signatures made with keys held in gpg-agent. Existing signatures are relabeled on upgrade, and older StartOS and start-cli versions keep working.
- **Dependencies are updated with security fixes**, including TLS certificate verification and handshake handling, HTTP/2 flow control, and XML parsing.
- **Remote requests using unconfigured loopback signing addresses are rejected.**

## Important

- A reverse proxy in front of the registry must forward `/icons/`.
- A registry serving StartWRT must set `startwrt: true` in its config (or pass `--startwrt`) so routers keep receiving the signature labels they understand.
