**start-registry 1.1.0 lets a registry describe itself, stream its index to clients, and be administered from the host it runs on.**

## Highlights

- **A registry can declare a description.** `info set-description` stores markdown — a `LocaleString`, so it can carry translations — and the marketplace shows it above that registry's services while it is selected.
- **A client can follow the index over a websocket instead of re-fetching it.** `db.subscribe` returns `/index` as it stands plus a continuation id; connecting to `/ws/rpc/<id>` streams its JSON patches. A caller can select `/index` or any subpath, and the endpoint stays unauthenticated.
- **An indexed package version advertises which installed versions can migrate into it**, so a client asking for an upgrade path is offered a version it can actually install. Entries already in an index keep their permissive value until that version is published again.
- **Package metadata carries hardware virtualization support** — a package can declare access to `/dev/kvm` with `hardwareVirtualization`, and manifests that omit the field remain compatible.
- **`start-registry` works on a host that listens on a non-loopback address.** A registry reachable from anywhere but the host itself binds `0.0.0.0:5959`, and every local command went out unauthenticated and came back `Unauthorized`. An explicit `--registry` URL is unchanged: the token still goes only to a loopback URL.
- **`os asset remove` can be run.** Its `iso`/`img`/`squashfs` subcommands now take `<VERSION> <PLATFORM>`, so one platform's entry can be dropped without removing the whole version and re-adding every other platform.
