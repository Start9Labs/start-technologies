**A one-fix patch release: a file model now parses with its shape exactly as written.** Update packages to 3.0.1, not 3.0.0.

## Highlights

- **A file model follows the shape you write.** A `z.looseObject` shape keeps the keys it doesn't declare; a `z.object` shape deletes them on the next `merge()`, `write()` or `update()`. A `z.discriminatedUnion` keeps the variant its discriminator names.

## Important

- **Never use `z.object` in a file model.** Build every file-model shape with `z.looseObject`, at every nesting level. Use `z.object` only for a file you have fully modeled and will always keep fully modeled — any key it doesn't declare is deleted without warning.
