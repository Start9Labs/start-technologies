## Novedades

- `start-cli auth token create --name <name>` crea un token de portador de StartOS para clientes de la API y lo muestra una sola vez.

- `--trust` en la instalación de paquetes y las actualizaciones del SO permite omitir explícitamente la confianza en el firmante. Desde StartOS 0.4.1 se requiere por defecto un firmante de confianza habilitado; la opción no elimina las comprobaciones de firma e integridad.
- Las actualizaciones de diagnóstico ya no requieren un argumento de registro que no tenía efecto.

- **`start-cli auth session kill` usa `--pubkey <key>` y `--token <id>`** para las sesiones que se quieren cerrar, en lugar de identificadores posicionales.

- Añade `disk format` para borrar una unidad y prepararla con una única partición Btrfs para las copias de seguridad de StartOS.

- Conserva valores multilínea del entorno de la imagen en los metadatos JSON de paquetes que usan Start SDK 3.1.2 o posterior.

- **Las configuraciones WireGuard pueden usar un endpoint independiente en hosts StartTunnel detrás de NAT.** `tunnel device show-config --endpoint` especifica un endpoint IPv4, IPv6 o DNS sin depender de la asignación WAN local. Requiere StartTunnel 1.5.0 o posterior.

## Seguridad

- Backup mount, backup information, package restore, and CIFS target add/update commands read passwords from a hidden prompt instead of positional arguments. Update automation to supply `BACKUP_PASSWORD` or `CIFS_PASSWORD`; `PASSWORD` remains the separate CLI authentication credential.
