## Nouveautés

- `start-cli auth token create --name <name>` crée un jeton bearer StartOS pour les clients API et ne l’affiche qu’une fois.

- `--trust` pour l’installation de paquets et les mises à jour du système permet d’outrepasser explicitement la confiance accordée au signataire. À partir de StartOS 0.4.1, un signataire de confiance activé est requis par défaut ; les vérifications de signature et d’intégrité restent obligatoires avec cette option.
- Les mises à jour de diagnostic ne nécessitent plus d’argument de registre sans effet.

- **`start-cli auth session kill` utilise `--pubkey <key>` et `--token <id>`** pour désigner les sessions à terminer, à la place des identifiants positionnels.

- Ajoute `disk format` pour effacer un disque et le préparer avec une seule partition Btrfs destinée aux sauvegardes StartOS.

- Préserve les valeurs multilignes de l’environnement des images dans les métadonnées JSON des paquets utilisant Start SDK 3.1.2 ou ultérieur.

- **Les configurations WireGuard peuvent utiliser un point de terminaison distinct sur les hôtes StartTunnel derrière un NAT.** `tunnel device show-config --endpoint` définit une adresse IPv4, IPv6 ou DNS indépendamment de l’affectation WAN locale. Nécessite StartTunnel 1.5.0 ou ultérieur.

## Sécurité

- Backup mount, backup information, package restore, and CIFS target add/update commands read passwords from a hidden prompt instead of positional arguments. Update automation to supply `BACKUP_PASSWORD` or `CIFS_PASSWORD`; `PASSWORD` remains the separate CLI authentication credential.
