## Neuerungen

- `start-cli auth token create --name <name>` erstellt ein StartOS-Bearer-Token für API-Clients und gibt es einmalig aus.

- `--trust` bei Paketinstallation und OS-Updates überschreibt die Vertrauensprüfung für Signierer ausdrücklich. Unter StartOS ab 0.4.1 erfordern diese Vorgänge standardmäßig einen aktivierten vertrauenswürdigen Signierer; Signatur- und Integritätsprüfung bleiben auch mit der Option verpflichtend.
- Diagnose-Updates benötigen kein wirkungsloses Registry-Argument mehr.

- **`start-cli auth session kill` verwendet `--pubkey <key>` und `--token <id>`** für die zu beendenden Sitzungen statt positionsgebundener Sitzungs-IDs.

- `disk format` löscht ein Laufwerk und richtet darauf eine einzelne Btrfs-Partition für StartOS-Sicherungen ein.

- Mehrzeilige Umgebungswerte von Images bleiben in JSON-Metadaten für Pakete mit Start SDK ab 3.1.2 erhalten.

- **WireGuard-Konfigurationen können auf StartTunnel-Hosts hinter NAT einen eigenen Endpunkt verwenden.** `tunnel device show-config --endpoint` gibt unabhängig von der lokalen WAN-Zuweisung einen IPv4-, IPv6- oder DNS-Endpunkt vor. Benötigt StartTunnel ab 1.5.0.

## Sicherheit

- Backup mount, backup information, package restore, and CIFS target add/update commands read passwords from a hidden prompt instead of positional arguments. Update automation to supply `BACKUP_PASSWORD` or `CIFS_PASSWORD`; `PASSWORD` remains the separate CLI authentication credential.
