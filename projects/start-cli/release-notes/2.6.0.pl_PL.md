## Nowości

- `start-cli auth token create --name <name>` tworzy token Bearer StartOS dla klientów API i wyświetla go tylko raz.

- `--trust` przy instalowaniu pakietów i aktualizowaniu systemu pozwala jawnie pominąć ocenę zaufania do podpisującego. Od StartOS 0.4.1 operacje te domyślnie wymagają włączonego zaufanego podpisującego; sprawdzanie podpisu i integralności pozostaje obowiązkowe także z tą opcją.
- Aktualizacje diagnostyczne nie wymagają już argumentu rejestru, który nie miał żadnego wpływu.

- **`start-cli auth session kill` przyjmuje `--pubkey <key>` i `--token <id>`** dla kończonych sesji, zamiast identyfikatorów sesji jako argumentów pozycyjnych.

- Dodano `disk format`, aby wymazać dysk i przygotować na nim jedną partycję Btrfs na kopie zapasowe StartOS.

- Zachowuje wielowierszowe wartości środowiska obrazu w metadanych JSON pakietów używających Start SDK 3.1.2 lub nowszego.

- **Konfiguracje WireGuard mogą używać osobnego punktu końcowego na hostach StartTunnel za NAT-em.** `tunnel device show-config --endpoint` ustawia punkt końcowy IPv4, IPv6 lub DNS niezależnie od lokalnego przypisania WAN. Wymaga StartTunnel 1.5.0 lub nowszego.

## Bezpieczeństwo

- Backup mount, backup information, package restore, and CIFS target add/update commands read passwords from a hidden prompt instead of positional arguments. Update automation to supply `BACKUP_PASSWORD` or `CIFS_PASSWORD`; `PASSWORD` remains the separate CLI authentication credential.
