**start-cli 2.5.0 signs requests and registry assets with an updated scheme, can keep its identity key in gpg-agent, and manages trusted OS update signers and per-gateway DNS.**

## Highlights

- **The identity key can live in gpg-agent.** Set `id-key-gpg: <key>` in the config (or pass `--id-key-gpg`) to sign with an Ed25519 key held by gpg-agent instead of `id.key.pem`. Requires GnuPG 2.3 or later.
- **Requests and registry signatures use an updated scheme.** Signatures made with `id.key.pem` carry their own Ed25519ph label.
- **Manage trusted OS update signing keys** with `server update-signers`.
- **Set DNS overrides per gateway** with `net dns set-static <GATEWAY> [SERVERS]...`; omit servers to restore automatic gateway DNS.
- **`package start` records running intent while critical tasks block execution and prints a warning.** The service starts automatically once those tasks clear.
- Complete `start-cli` commands, nested subcommands, and options with Tab in new Bash shells, without editing a shell profile.
- **Dependencies are updated with security fixes**, including TLS certificate verification and handshake handling, HTTP/2 flow control, and XML parsing.

## Important

- Managing a server or publishing to a registry requires StartOS 0.4.0.3, StartTunnel 1.4.0, or start-registry 1.2.0 or later. Reading from older registries still works.
- Servers running StartOS 0.4.0.3 or earlier cannot verify registry assets signed only by a gpg-agent key.
- `package start --force` is removed. Remove `--force` from scripts.
