**StartWRT 1.1.0 lets devices open their own port forwards, identifies devices that never tell you their name, and provisions eMMC boot firmware so a DIY board boots without its microSD card.**

## Highlights

- **Devices can open and renew their own port forwards** using the standard PCP and UPnP protocols — a StartOS server configures itself behind the router, and game consoles and torrent clients are covered too. It is **off by default**: enable it per device with "Allow automatic port forwarding" on that device's page. A device can only ever forward ports to itself, manual rules always win, and ports the router itself answers on are refused.
- **Several devices can share one external port by hostname.** A device can claim a name on a shared port such as 443, and the router delivers each TLS connection to whichever device owns the name it asks for — so several services, on one server or many, can live behind a single port. Remote access to the router's own interface keeps working alongside it.
- **Devices that never share a hostname are named by operating system or vendor** — `Windows device (3af2b1)` or `Apple device (3af2b1)` in place of an opaque `device-3af2b1`. A real hostname still takes over when one appears, and names you assign always win.
- **A DIY BananaPi BPI-F3 now boots from eMMC.** The flash wizard, in-app updates and a check on every boot write the release's own eMMC boot firmware, self-healing a board whose factory left it empty or carrying an incompatible bootloader.
- **MT7915-based Wi-Fi modules now work on DIY builds** — the image ships their firmware alongside the MT7916 firmware.
- **The interface notices a newer firmware and catches up.** An update installed from the current tab reloads the page once the router is back; one applied elsewhere offers a Reload button rather than reloading over unsaved work.
- **Publishing a port the router itself answers on asks for confirmation** rather than silently cutting off remote access, SSH or an inbound VPN.
- **Disabled VPNs are no longer offered as a profile's route or as a chain target** — picking one used to send that traffic straight out your Internet connection while every screen reported success.
- **The StartWRT user guide is published** at [docs.start9.com/start-wrt](https://docs.start9.com/start-wrt/), including a Hardware page with the router's specifications and reference schematic.

## Important

**The IPv6 "Reserve" option is gone.** Devices choose their own IPv6 addresses, so a router cannot reserve one — the toggle never worked. A device's IPv6 address is now shown read-only, and a published-port rule follows the device's current address on its own.

**The Start9 DDNS provider option is gone** until that service launches. A Dynamic DNS configuration saved with it now reads back as disabled; pick one of the supported providers to re-enable it.
