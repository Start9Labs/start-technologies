## Neuerungen

- **`start-tunnel auth session kill` verwendet `--pubkey <key>` für jede zu beendende Sitzung** statt positionsgebundener Sitzungs-IDs. Der RPC-Aufruf `auth.session.kill` verwendet `pubkeys` statt `ids`; `auth.session.list` gibt `{ pubkeys, tokens }` zurück.

- Dialoge zum Hinzufügen von Geräten öffnen sich erst nach dem Laden der Subnetzdaten.

- **WireGuard-Konfigurationen können hinter NAT einen eigenen Endpunkt verwenden.** Der Konfigurationsdialog übernimmt standardmäßig den Host der Browser-URL und akzeptiert eine geänderte IP-Adresse oder einen DNS-Namen. `device show-config --endpoint` bietet dieselbe Einstellung pro Konfiguration, unabhängig von der für SNAT und Weiterleitungen verwendeten WAN-Adresse.

- Forwarded ports no longer occasionally fail to accept connections because the host was using the port for an outbound connection.

## Wichtig

Wählen Sie einen Endpunkt, der vom Gerät erreichbar ist; ein HTTPS-Reverse-Proxy leitet WireGuard-UDP möglicherweise nicht weiter. Der konfigurierte WireGuard-Port bleibt erhalten. Die Konfigurationserzeugung per CLI mit einer nicht öffentlichen WAN-Zuweisung erfordert `--endpoint`. Bereits auf Geräten installierte Konfigurationen bleiben unverändert.
