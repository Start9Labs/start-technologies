## Nowości

- **`start-tunnel auth session kill` przyjmuje `--pubkey <key>` dla każdej kończonej sesji**, zamiast pozycyjnych identyfikatorów sesji. RPC `auth.session.kill` przyjmuje `pubkeys` zamiast `ids`, a `auth.session.list` zwraca `{ pubkeys, tokens }`.

- Okna dodawania urządzeń nie otwierają się przed załadowaniem danych podsieci.

- **Konfiguracje WireGuard mogą używać osobnego punktu końcowego, gdy StartTunnel działa za NAT-em.** Okno konfiguracji domyślnie używa hosta z adresu URL przeglądarki i przyjmuje zmieniony adres IP lub nazwę DNS. `device show-config --endpoint` zapewnia to samo nadpisanie dla danej konfiguracji, niezależnie od adresu WAN używanego do SNAT i przekierowań.

- Forwarded ports no longer occasionally fail to accept connections because the host was using the port for an outbound connection.

## Ważne

Wybierz punkt końcowy dostępny dla urządzenia; odwrotne proxy HTTPS może nie przekazywać ruchu UDP WireGuard. Skonfigurowany port WireGuard pozostaje bez zmian. Generowanie konfiguracji przez CLI przy niepublicznym przypisaniu WAN wymaga `--endpoint`. Konfiguracje już zainstalowane na urządzeniach pozostają bez zmian.
