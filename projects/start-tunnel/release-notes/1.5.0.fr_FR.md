## Nouveautés

- **`start-tunnel auth session kill` utilise `--pubkey <key>` pour chaque session à terminer**, à la place des identifiants positionnels. Le RPC `auth.session.kill` reçoit `pubkeys` au lieu d’`ids` et `auth.session.list` renvoie `{ pubkeys, tokens }`.

- Les dialogues d’ajout d’appareil ne s’ouvrent plus avant le chargement des données des sous-réseaux.

- **Les configurations WireGuard peuvent utiliser un point de terminaison distinct lorsque StartTunnel est derrière un NAT.** Le dialogue reprend par défaut l’hôte de l’URL du navigateur et accepte une adresse IP ou un nom DNS modifiés. `device show-config --endpoint` offre le même réglage par configuration, indépendamment de l’adresse WAN utilisée pour le SNAT et les redirections.

- Forwarded ports no longer occasionally fail to accept connections because the host was using the port for an outbound connection.

## Important

Choisissez un point de terminaison accessible par l'appareil ; un proxy inverse HTTPS peut ne pas transmettre le trafic UDP de WireGuard. Le port WireGuard configuré est conservé. La génération de configurations par CLI avec une affectation WAN non publique nécessite `--endpoint`. Les configurations déjà installées sur les appareils restent inchangées.
