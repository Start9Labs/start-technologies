## Novedades

- **`start-tunnel auth session kill` usa `--pubkey <key>` para cada sesión que se quiera cerrar**, en lugar de identificadores posicionales. El RPC `auth.session.kill` recibe `pubkeys` en lugar de `ids` y `auth.session.list` devuelve `{ pubkeys, tokens }`.

- Los diálogos para añadir dispositivos no se abren antes de cargar los datos de subredes.

- **Las configuraciones WireGuard pueden usar un endpoint independiente cuando StartTunnel está detrás de NAT.** El diálogo usa por defecto el host de la URL del navegador y acepta una IP o un nombre DNS editados. `device show-config --endpoint` ofrece el mismo ajuste por configuración, independientemente de la dirección WAN usada para SNAT y reenvíos.

- Forwarded ports no longer occasionally fail to accept connections because the host was using the port for an outbound connection.

## Importante

Elige un endpoint al que el dispositivo pueda llegar; un proxy inverso HTTPS podría no reenviar el tráfico UDP de WireGuard. Se conserva el puerto WireGuard configurado. La generación de configuraciones por CLI con una asignación WAN no pública requiere `--endpoint`. Las configuraciones ya instaladas en los dispositivos no cambian.
