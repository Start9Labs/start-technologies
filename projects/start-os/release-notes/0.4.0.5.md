**0.4.0.5 fixes service HTTP authentication, command input, and public-domain networking.**

## Highlights

- **HTTP authentication covers both connection types.** Service HTTP proxy authentication policies apply to plaintext and TLS connections.
- **Raw TLS services retain client addresses.** Services using raw TLS without HTTP proxying receive the original client source IP address.
- **Piped commands finish when their input ends.** Commands such as `cat` run through `package attach` receive EOF from piped or redirected stdin and exit normally.
- **Add public domains to port-range interfaces.** Services whose interfaces expose a range of ports can add public domains from the web UI or CLI.

## Important

- Services with HTTP proxying enabled now see StartOS as their TCP peer on plaintext connections. Client addresses are available through `X-Forwarded-For` when the binding enables header generation.

- Downgrading to an earlier StartOS version restores that version's HTTP authentication behavior, including its unprotected plaintext connections. Downgrades are blocked for HTTP authentication policies without a TLS wrapper; add TLS to those bindings before downgrading.
