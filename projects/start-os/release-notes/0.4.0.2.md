**0.4.0.2 adds a trusted-network switch for plaintext addresses, hardware virtualization for services, and a long list of networking, backup and interface fixes.**

## ⚠️ Updating from 0.3.5.1

> **The only way to update from 0.3.5.1 is by following the [0.4.0 Update Guide](https://docs.start9.com/start-os/update-040.html) precisely.** This is a sensitive update between two essentially distinct operating systems — skipping steps or improvising can result in data loss.
>
> If anything goes wrong, **stop and [contact support](https://start9.com/contact)** — do not attempt to troubleshoot on your own.

## Highlights

- **Type a service's domain without `https://` and its web interface opens over HTTPS**, on each network where that domain is assigned.
- **Mark a gateway secure and every service's plaintext address is offered over it** — the server's LAN addresses, its `.local` name and its private domains, on that gateway's directly connected and routed private networks. Mark a gateway secure only when you control every device on those networks. See [Gateways](https://docs.start9.com/start-os/gateways.html).
- **Services can use your processor's virtualization support**, so packages built around QEMU, Firecracker and similar workloads can run virtual machines. StartOS grants it only to packages that ask for it.
- **Apps that pin your server's certificate stop warning about it.** Sparrow, the Electrum clients and anything else that remembers the first certificate it is shown now see the same one across every route to that name. See [Public IP](https://docs.start9.com/start-os/public-ip.html).
- **Desktop sync clients and API pollers stop dropping in and out.** Nextcloud Desktop and clients like it showed a recurring "Network error" that cleared itself seconds later; connections through the StartOS proxy now close cleanly, which is the signal those clients wait for.
- **Restoring a service from a backup is many times faster** — a restore that took 42 minutes takes a couple.
- **Restoring from a backup, or transferring to a new drive, keeps your server's name** instead of renaming it to `start9`.
- **Installed services can be shown as a grid of tiles**, and your choice follows you to any browser pointed at this server.
- **Private domains keep working on networks that block PCP.** Where a network filters the protocol StartOS uses to ask a gateway for a route, it now asks over UPnP instead.

## Important

**Your server's name is now its `.local` address.** There was previously a display label and a separate `.local` address derived from it; there is now one name, edited under `System > General Settings` and accepting up to 32 lowercase letters, numbers and hyphens. A name outside those rules is repaired on update. **Two `start-cli` commands change with it**, so update any unattended-install or provisioning script: `setup execute` no longer takes `--name`, and `server set-hostname` now takes one required hostname.

**The NVIDIA images now use NVIDIA's open kernel modules.** This is what makes current cards work at all — an RTX 50-series, an RTX PRO 6000 or an NVIDIA GB10 can only be driven by these modules, and GeForce RTX 20-series, Quadro RTX and newer are supported. **A GeForce GTX 900-series or 10-series card, a Titan X or Xp, or a Tesla M40, P40, P100 or V100 will no longer be driven by the NVIDIA images.** If you rely on one of those, stay on 0.4.0.1 or use the Standard image, whose open-source driver still provides display output without GPU compute.
