# Full-disk encryption contract

FDE is opt-in and targets UEFI systems with TPM 2.0 and Secure Boot. The immutable OS image and the encrypted data drive remain separate. The admin password independently unlocks the data volumes; TPM availability is not a prerequisite for recovering data with that password.

Enabling FDE owns the enrollment workflow; enrollment is not a separate prerequisite delegated to the user. Before confirmation, the enable UI prominently warns: “After every restart, your server and its services will remain offline until you unlock it with your password.” Enabling requires explicit acknowledgment of that consequence. The restricted password-entry page is the pre-unlock access surface, not an available normal server or service. Persisted enable intent, pending enrollment and observed active FDE must remain distinguishable; requesting enrollment cannot be reported as completed protection.

`fde::enrollment::begin` owns the initial signing identities and firmware request. The private database stores separate RSA image, P-256 manifest and P-256 policy authorities before firmware mutation. Native `ukify genkey` supplies the image certificate; its Python cryptography provider belongs to the UEFI package dependencies. A temporary 16-character approval code authorizes the shared native MOK request, not data unlock or recovery. Adding the image certificate refreshes authentication for all pending certificates without cancelling them; the enable UI must identify this shared approval code and the requested certificates.

`util::mok::request_enrollment` preserves shared pending subjects when refreshing authentication, including subjects in unrecognized signature lists. Native `mokutil --refresh-import-auth` updates `MokAuth` without rewriting `MokNew`; legacy DKMS refresh uses this owner instead of globally revoking imports. Authentication-write failure retains the pending request for retry. Pending membership alone does not establish that the intended password was stored. The image build extends its installed Debian mokutil source through `build/image-recipe/mokutil`, retaining the native password codec, variable backend and package build. It carries the corresponding modified source at `/usr/share/doc/mokutil/startos-source.tar.gz`. Enrollment rejects an older tool before import mutation; binary-only deployments require the matching full image for this operation.

The public `config/fde/enrollment.der` file reserves request authentication for that coordinator. Legacy DKMS/shadow helpers must not revoke or refresh the shared request while that reservation exists. Certificate observations use transient native inputs; publication of the shared-authentication reservation precedes an approved import, not a read-only probe. Failed imports retain durable identities, approval code and reservation for an acknowledged retry. Refused re-enrollment without an approval code clears its reservation. After every required certificate is observed enrolled, the coordinator removes the stored code and reservation. This file records ownership intent, never enrollment success or active protection. Authenticated `server.fde.status` reports supported-platform scope and persisted enable intent without decoding signing keys. `server.fde.begin-enable` requires the current password and an explicit restart acknowledgment, rejecting the reserved DEFAULT credential before enrollment side effects. After native firmware approval it prepares administrator authority and a freshly authorized unpublished configuration candidate. `preparedGeneration` identifies that candidate, not a complete boot generation, public builder-source admission, EFI activation or active protection. The System encryption settings use the generated RPC types and display every required certificate's native observation. The firmware comparison fingerprint is SHA-1 of DER, matching MokManager 15.8; SHA-256 remains available separately and SHA-1 never authorizes boot. Setup and FDE share firmware-menu instructions while supplying their own credential step. The enable UI reports completed enrollment separately from pending activation.

`fde::memory::requires_protection` owns the no-swap rule for persisted signing or disk authority. Enrollment stops the managed ZRAM device before generating signing keys, without changing the saved ZRAM preference or disabling unrelated swap. Initialization and daemon restart inspect untyped authority before migrations, typed normalization, key repair or account-key decoding; initialization suppresses ZRAM while that authority exists. Failed enrollment without persisted authority attempts to restore previously active managed ZRAM. It does not enable a previously inactive device or restore swap under persisted authority. The explicit ZRAM setter shares the password/enrollment mutex and rejects activation under that rule. Its ordinary no-authority path reconciles observed kernel state rather than treating saved intent as current availability.

`build/dpkg-deps/uefi.platforms` owns the supported generic target list for both package selection and runtime enrollment admission. Board and unknown variants reject before enrollment side effects.

## Bootstrap identity

The locked RPC context retains one unpersisted temporary proof identity through its lifetime. Unverified disk configuration cannot select it. Explicit startup callers admit that scope; normal-product callers reject it without recording fingerprint history. The ordinary startup owner's unencrypted account/setup identity mirrors remain part of protected activation's credential-copy reclamation obligation.

Boot attestation gates the private TLS identity used by the password-entry page and the network credentials needed to reach it. It does not release a data-volume password or data-decryption key. A failed attestation cannot silently enroll changed boot state or fall back to presenting the valid unlock identity.

The measured execution chain must authenticate the kernel, initramfs, effective command line, rootfs and persistent overlay before bootstrap credentials are released. The authorized policy must bind the verified loader path: an alternate trusted kernel running an unsigned initramfs must not gain access by replaying public UKI or filesystem measurement events. Filesystem contents must remain integrity-protected after verification. Merely authenticating a filename or measuring a mutable directory does not satisfy this contract.

`start_core::fde::bootstrap` authenticates and encrypts the bootstrap payload. `start_core::fde::tpm` seals its random encryption key to a P-256-authorized policy over SHA-256 PCRs 0, 2, 4, 7, 11, 12, 13, 14 and 15, restricted to `Unseal`. The policy reference binds the canonical bank/register selection; an authorization for a weaker selection cannot unlock the object. Firmware and option ROM measurements are pinned alongside Secure Boot and shim MOK policy. PCR 4 binds the loaded application sequence; PCR 11 belongs to the UKI measurement chain; PCR 15 binds the verified rootfs and overlay. Unexpected firmware or trust-policy changes require trusted re-enrollment, not automatic resealing. The policy-signing private key belongs on the encrypted data drive. The TPM policy authorization and the overlay manifest signature are distinct messages. TPM helpers must not inherit TSS diagnostic verbosity: debug output includes session keys. The shared command boundary clears `TSS2_LOG`, retaining the library's default diagnostics.

`fde::tpm::MeasurementProfile` pairs public expected PCR values with their authorization. Reuse as authorization inputs requires signature verification and recomputation of the TPM policy digest from those values. A valid signature on a policy digest alone does not authenticate adjacent measurement metadata. Observed post-phase PCR values are not future pre-phase predictions.

`start_core::fde::credentials` carries encrypted TLS material and NetworkManager profiles without a data-unlock password. Local certificate issuance shares the normal server's intermediate-only issuer and certificate cache; the bootstrap issuer excludes the root CA private key. ACME snapshots contain the selected providers' settings, accounts and cached identities, and reuse normal issuance and challenge handling. Leaf identities share the normal certificate-chain type and TLS configuration builder. NetworkManager keyfile discovery is shared with the existing saved-profile owner. Bootstrap keyfiles are materialized with private permissions beneath `/run`, then removed individually during handoff; saved data-drive profiles remain authoritative.

`net::net_controller::plan_host_exposure` owns exposure decisions for normal and standalone consumers. Standalone interface discovery and vhost listeners accept saved input, interface watches and injected TLS sources without constructing private-database state.

These primitives alone do not establish the measured boot chain or enable FDE on a server.

## Restricted startup

`build/lib/scripts/fde-boot-mode` owns the FDE boot-method name. The UKI builder requires one matching `BOOT` command-line parameter; the reviewed initramfs control plane and daemon consume that same name. The daemon selects its protected workflow from the authenticated command line, never a public disk marker. Selection is not attestation: protected execution also requires the private, root-owned RAM handoff produced after verified filesystem measurement and bootstrap release. Missing or invalid handoff fails closed. Protected startup and restart errors cannot fall into the ordinary diagnostic/setup surface.

Before PID1 starts, `fde::boot_services` selects a native bootstrap target in the running RAM upper, without changing working configuration. Its graph retains system initialization, NetworkManager, resolver, clock, discovery and `startd`, rather than pulling normal multi-user/socket/timer activation. OpenSSH's existing `sshd_not_to_be_run` condition gates both its service and socket. Native emergency/rescue/debug-shell conditions retain the same private gate. Signed command lines reject alternate init, systemd startup overrides and native runlevel selectors.

After retained data authority and ordinary initialization succeed, the daemon restores the configured default target and SSH marker, clears its RAM gate, waits for the configured native target job, then retires the bootstrap target. Saved filesystem entries preserve administrator intent, including graphical targets and dangling marker symlinks; authoritative replacements win over an old saved entry. Restoration resumes after interruption between removing a temporary link and restoring its saved entry. These availability gates are not attestation or persisted encryption authority. Normal boot never installs this profile.

`fde::unlock::UnlockContext` exposes exactly `state` and `unlock`, without an account database, management authorization or device-key enrollment. It reuses startup possession identities, native encrypted-RPC admission, nonce/clock policy and normal ingress-aware signing names. Secure-session provenance retains the connection's native origin for the existing login rate limiter. The browser follows the generated `locked` API state to its HTTPS password-entry page and does not query unavailable diagnostic/network methods there. Password whitespace remains exact.

Accepted unlock work survives requester cancellation while the runtime lives. Typed outcome writes drain through the native transport deadline before ordinary initialization replaces the restricted router; peer loss does not undo an accepted unlock or promise receipt. The explicit password captures mapper/UUID-bound volume keys in protected memory, then the native root keyring retains them for this OS boot. Protected data import accepts those opaque keys, never an optional/default password. Same-boot daemon recovery reuses retained authority and recognizes already mounted, read-write Btrfs targets by their actual block-device identity. Reboot loses this cache and requires another password. Pool cleanup closes its own LUKS mappings, not unrelated device-mapper mappings or the verified root. Ordinary import closes stale unmounted pool mappings before retrying. Data-drive creation reuses the OS-install sysfs holder graph, rejecting busy device-mapper holders or failed graph inspection before physical-volume writes, without globally removing mappings.

`BootstrapNetwork` captures the server UI binding, gateway intent, allocated ports and Wi-Fi policy; it excludes other server ports and binding ranges. The standalone watcher publishes saved intent before discovery, while clearing stale observations. Normal and restricted networking share host-address derivation, exposure reconciliation, TLS/vhost authorization, port-map ownership, DNS and WireGuard mDNS injection. The restricted runtime creates no placeholder private database. Native NetworkManager synchronization binds captured private RAM profiles at its canonical saved-profile directory; after unlock the same owner rebinds authoritative data-drive profiles before captured files are removed. ACME uses its existing scoped RAM database and native provider selection; handoff preserves current settings/accounts and healthy identities while accepting eligible renewed cache entries.

The enrollment settings prepare administrator authority after firmware approval without activating this boot path. Complete authenticated generation and durable EFI activation remain required before enabling it on an installation. Firmware/reboot execution, whole-caller reservations and complete process-death recovery still require their scoped verification.

## UKI construction

`build/lib/scripts/fde-build-uki` embeds the kernel, initramfs, effective command line and OS release in a native-architecture UKI, signed using the enrolled RSA Secure Boot identity. That private key belongs on the encrypted data drive and is distinct from the P-256 policy authority. PCR11 prediction uses the final image's actual virtual section contents through systemd tooling; Authenticode signing timestamps do not select boot state.

The authorized application sequence is firmware → shim → UKI, without GRUB or another command interpreter. Shim directly loads the machine-signed UKI from its second-stage EFI path. The supported measurement profile includes the whole UKI, not a separately measured embedded kernel. Extra applications, returned-image fallback paths and unsupported firmware measurement behavior fail closed; they are not learned as replacement policy. Vendor and Microsoft firmware trust may remain enrolled. The MOK certificate must permit image signing; a module-only certificate is insufficient.

PCR4/PCR7 prediction must validate the current event-log replay against live PCRs and preserve the trusted firmware/shim prefix. The future UKI and its actual enrolled authority determine the replacement events. The enable workflow starts enrollment from a trusted running installation or recovery environment; public-log consistency alone does not establish that trust. PCR14 binds MOK policy, including unused allowlist and denylist entries.

`start_core::fde::loader` captures a caller-authenticated current chain, including legacy GRUB and kernel artifacts, and retains only the firmware/shim prefix. Future predictions pair the exact UKI application digest with its enrolled MOK authority event. The validated legacy tail is not a future authorization. Baselines belong in the encrypted database, never public boot configuration.

The helper creates a UKI and a `.pcr11` companion in a private staging generation on a hard-link-capable filesystem. The companion contains 64 lowercase hexadecimal digits and a newline, describing SHA-256 PCR11 before any initrd phase events. The pair is not independently atomic: the enclosing complete generation owns publication. Existing output files are not replaced on errors.

Activation makes the compatible rootfs, overlay and policy generation durable before replacing the complete EFI image on the ESP. Old dependencies remain until activation is durable. The old UKI may select only overlays with a compatible rootfs and an authorization for that boot/filesystem combination. FAT replacement does not guarantee boot availability across a power cut; signature and TPM failures remain fail-closed. The supported profile excludes external stub inputs by requiring empty PCRs 12 and 13 when authorizing. This excludes external parameters, credentials, configuration/system extensions, nondefault UKI profiles and addons; public boot metadata cannot authorize them.

## Boot selection

`fde::boot::Descriptor` pins one rootfs filename and the manifest/policy verification keys inside the signed initramfs. Unsigned configuration cannot replace those keys or choose a non-FDE boot mode. Complete generations live under `config/fde/generations`; their public policy files remain outside the hashed configuration image to avoid a filesystem-policy hash cycle.

Generation metadata files and leaf directories require passive type admission before opening or listing. Symlinks and special files are not metadata providers. Policy selection, store enumeration, publication and pruning share the directory owner; metadata/image reads share the regular-file owner. Callers keep source paths stable throughout admission and verification; these checks are not path-lifetime protection.

Selection reuses `os_overlay::verified_generations` ordering and admits the newest candidate whose authenticated policy matches the observed boot plus its anticipated filesystem event. A newer signed filesystem without a matching boot authorization does not displace an older compatible generation. `Descriptor::mount` opens and fully reads both signed verity mappings and mounts them as read-only SquashFS. `MountedGeneration::measure` checks the live boot again before extending PCR15. Mount guards remove mappings after successful unmount, or transfer both resources to the boot owner for handoff. Selection alone cannot release credentials; dependent mounts must end before their mappings close.

`startbox start-fde-prepare` takes the OS-volume mount and target root mountpoint. It reads the descriptor from the authenticated FDE initramfs, not disk configuration; guarded release composes the running and working roots before measuring the protected filesystems and decrypting the bootstrap snapshot. Its caller must terminate on error without ordinary-boot fallback or an interactive shell. The signed FDE mount route waits up to 30 seconds for the local kernel TPM resource-manager device `/dev/tpmrm0`, then binds that device TCTI to the preparation command alone. Device existence is sufficient; TPM nodes need not have udev database entries. Readiness failure terminates before preparation. Other TPM consumers retain their transport selection. The normal initramfs does not invoke it.

The boot owner retains nonsecret `configuration.json` in private RAM through daemon restarts: actual root/config/working-upper references, the authenticated descriptor/profile and verified rootfs digest. Credential-only `handoff.json` is removed after authoritative data/network handoff. Retained references do not establish durable EFI publication, and live post-phase PCR11 cannot replace the stored pre-phase profile.

The preparation helper excludes active swap and piped core handlers, disables its own dumpability and inherits a zero core limit into TPM tools. These conditions must remain stable until release finishes. Runtime identities and TPM workspaces use private `noswap` tmpfs mounts; the private handoff remains RAM-only after helper exit. This initramfs protection does not establish the separate OS-boot-lifetime volume-key cache or protect later daemon handling by itself.

`fde-harden-initramfs.mjs` delegates to the shared `fde-initramfs-control.mjs` library and transforms the reviewed initramfs-tools 0.148.4 control plane in a caller-owned private tree. It rejects changed or unknown providers/configuration before mutation. The transform fixes the FDE boot route and removes resume, live boot, keymap execution, runtime parameter sourcing and automatic `/usr` mounts. Ordinary generated images are not transformed.

The lower-only `OverlayFs::read_only` view has no writable upper/work directories and a distinct mount identity. Source admission retains signature selection and native public/runtime/overlay setup when its waiter is cancelled. An abandoned completed source unwinds its dependent mounts and mapping. This requires an active async runtime; the caller reserves the source mountpoints through setup and cleanup, not merely until a path disappears. The source view alone does not execute a generator.

`BuildSource::run_script` consumes that owner and returns script stdout after execution and source teardown. Its entry point is a regular file resolving under the verified view's `/usr`, outside writable scratch. Runtime-image and entry-point containment share one path owner. Scratch and proc mountpoints cannot be aliases that escape or shadow public providers. Private `noswap` tmpfs mounts supply `/dev`, `/run`, `/tmp` and `/var/tmp`; the device view exposes only null, zero and kernel entropy devices. Native util-linux creates private mount/PID/network/IPC/UTS namespaces and proc before running the packaged Node in the source root with a cleared environment. No running/working configuration, data volume, host network or host device tree is imported. Script arguments and stdin are data interpreted by the admitted script, not alternate entry points. Normal success and command failure unwind scratch before public mappings; caller cancellation retains the entire operation while the async runtime remains active. Verity and source jobs share this retained-operation primitive. An owned operation's panic resumes with its original payload rather than becoming a filesystem error. This is not process-death recovery or a complete image builder. Unsigned assembly composes the native production/archive owners; complete source/closure authority and enable/signing/publication integration remain separate obligations.

`runNativeProducer` in `fde-initramfs-producer.mjs` runs admitted native production in util-linux PID and private mount namespaces. Ordinary producer exit ends every descendant, including detached writers, before success or producer-exit rejection reaches the archive owner. Source providers and the private workspace remain owned throughout the call, and the source root is a mountpoint. Launcher death is an error, not a completed-production proof. This primitive does not provide source-root setup, process-death recovery or the complete generator caller.

`withPrivateInitramfs` in `fde-initramfs-generation.mjs` owns a fresh private archive/capture workspace through production, native-stream verification and completed consumption. It passes capture paths only to the trusted producer and removes the workspace on production, verification or consumption failure as well as success. The producer must admit sources and executable closure before capturing, and join all writers before returning; the consumer completes archive use before returning. This lifetime owner does not supply source authorization, closure auditing or publication.

`withAssembledInitramfs` composes that lifetime with reviewed public configuration/source admission, private native hooks and required boot-module collection, namespace-owned native generation, completed-tree preparation and archive verification before consumption. Its kernel selection comes from the single source module tree, not the running kernel. Additional source hooks reject before execution. `fde-assemble-initramfs.mjs` requires a caller-supplied public descriptor file and writes an unsigned candidate create-only; neither operation supplies signing authority or changes the ordinary initramfs. `fde-prepare-initramfs.mjs` composes provider/dependency, kernel-module and linker-cache admission before control-plane hardening, then copies the operation-owned public descriptor into the generated tree. Empty input, redirected ancestors and an occupied descriptor leaf reject rather than overwriting another file. No private bootstrap payload, configuration tree or signing authority enters the public producer. The generation owner requires every `bootModules` entry to resolve against the admitted candidate before packaging, including native built-ins; an internally valid subset missing a required module rejects. Collection uses native `manual_add_modules` and availability uses native `modprobe --show-depends`, sharing the runtime's required-module list.

Enrollment connects public descriptor insertion and encrypted bootstrap configuration preparation, but not final effective configured runtime, signing or durable publication. Complete helper/runtime/plugin/NSS/configuration/EARLY admission and exceptional launcher-death ownership remain signing prerequisites. A successfully assembled candidate is not authorized for protected boot.

`fde-initramfs-archive.mjs` checks provenance of a private generated gzip initramfs: native-generated uncompressed prefixes match byte-for-byte, and the complete decompressed main stream matches its native-generated CPIO source. The producer must capture those sources after its executable-closure audit and exclude concurrent writes through consumption. Public proof files cannot authorize an image. Native extraction alone is insufficient: `unmkinitramfs` 0.148.4 does not inspect multiple compressed archives, and extraction can omit a later archive the kernel consumes. This provenance check delegates decompression to zlib and requires complete compressed-input consumption, including bytes following zero padding; it neither parses CPIO nor establishes arbitrary archive validity.

The build-time helpers support the Node 20.19 runtime already present in the public container-runtime image. Reuse requires its shared libraries and externalized `/usr/share/nodejs` builtin data in the admitted source namespace. The library/CLI split preserves symlink invocation without runtime-specific main-module detection. This does not install Node in the boot initramfs or establish the complete on-device builder namespace.

These helpers are not a complete image builder or executable-closure audit. Complete source/signing ownership, helper/runtime/configuration/plugin/EARLY admission, authenticated UKI/profile publication and activation integration remain prerequisites before signing or activating an FDE image.

## Persistent overlay

Authenticated enable/commit authorizes the whole captured prospective configuration, including executable, library, NSS and OpenSSL-provider overrides. A later capture needs fresh authorization; a snapshot hash or verity tree supplies integrity, not that authority. `fde::generation::prepare_configuration` retains the selected public-image mapping and unlocked data tree, captures configuration in private `noswap` RAM, and queries the actual prospective namespace before private projection and manifest signing. Current, native-default and prospective HostKey paths share the native SSH query owner. Native NSS retains the caller's network access; every HostKey query has a thirty-second deadline. Preparation consumes a disposable data-tree view, never the live system mount guard. The query's read-only recursive bind covers cloned child mounts while host-side projection retains writable data access. Read-only recursive clones are private; writable recursive clones are slaves of their source, receiving its mounts without propagating unmounts back. Nonempty idmapped mount-tree views retain existing child mounts across staging retirement, but not later source mounts. Empty idmaps preserve the inner filesystem's propagation. Ordinary and guard-owned recursive retirement retain native propagation, releasing copies held by other mount namespaces. Privatizing a retiring nested tree strands those copies; source isolation belongs to clone creation. Native mount descriptors support file and directory roots. Cache ownership excludes new users through that retirement. This private execution view is separate from public-only `BuildSource`; neither view silently masks authorized configuration. The returned legacy replacement plan contains paths rather than temporary source readers and survives capture teardown. `capture_configuration` performs the read/query epoch without writing data or the generation store; private projection follows that epoch. Its immutable RAM capture and retained mounts outlive native queries. The base image remains reserved through manifest preparation. Durable complete-boot publication and compatible EFI activation remain separate obligations.

`fde::capture` connects enrollment to this preparation after fresh password/acknowledgment and administrator setup. A private native operation owns a stable filesystem read epoch: canonical running/working overlay writes reject, the dedicated protected-boot RAM filesystem containing both raw uppers is readonly, and OS/main/package Btrfs writes wait during capture and native queries. This is filesystem writer exclusion, not application-transaction atomicity or a snapshot of remote NSS peers. The operation has a 300-second availability deadline. `PatchDb::pause_mutations` waits for value mutations before the read epoch while keeping cached reads and subscriptions available, including DNS forwarding; a frozen persistence writer must not hold the Store lock ahead of those reads. The cached database snapshot supplies the UI-only network plan, intermediate TLS issuer and enabled UI ACME state. Capture never issues certificates or mutates persistence while paused. Native saved-profile discovery completes before filesystem thaw; owned, zeroizing profile values and TLS authority survive teardown in private memory. After thaw and database resume, the existing TPM/bootstrap owner seals these credentials, and the encrypted envelope replaces `etc/startos/fde-bootstrap.json` in the unpublished configuration before private projection. This is configuration preparation; public descriptor insertion into an unsigned initrd does not complete generation publication or activation.

The native operation unit owns read-epoch restoration across helper/requester death. Stop kills its main producer before thawing, then native control-group teardown joins descendants before captured output is consumed. Thaw precedes waiting for descendants blocked on frozen filesystems. Final cleanup restores only originally writable overlay superblocks and removes its nonsecret request. Raw private captures use unswapped process/RAM storage and anonymous file descriptors, not public output files. This does not establish complete enable cancellation, publication recovery or firmware behavior.

Native OS image/configuration mutations and capture share the image-store reservation. Updates retain it across pruning, download and native upgrade; native maintenance scripts acquire the same kernel file lock. Inherited descriptors must identify the actual lock file, not merely carry an environment claim. The shared path/descriptor-field owners bind Rust and shell callers; the guard remains alive through native child completion. Capture rejects a busy reservation rather than waiting behind an interactive package operation.

The persistent overlay is an independently signed squashfs. Private signing keys, password verifiers, SSH host keys and saved NetworkManager keyfiles require encrypted-data placement before public configuration publication; activation must retire legacy boot-overlay copies. This migration is a prerequisite for the initial generation, not a property signatures provide. `fde::private_config::ProjectedConfig` stages those files on caller-retained encrypted data, preserving native ownership, modes, parent traversal, xattrs and hardlink identity. Public snapshots contain runtime references, not private file contents or attributes. Staging leaves legacy files untouched; a retry allocates a fresh candidate rather than overwriting an earlier authority. A resumed projected generation synchronizes its live backing files rather than copying stale legacy credentials over them. Native root-deletion markers retain their semantics. Synthetic version directories remain traversable independently of the configuration container's permissions; credential parent permissions remain authoritative. Native default and prospective SSH HostKey paths must come from the admitted prospective root; native Includes resolve in that namespace. Installer-named host-key files remain private even when their algorithms are no longer configured. Saved-profile filename admission shares the native NetworkManager owner; regular keyfiles and their hardlink aliases become private references without classifying neighboring notes or certificates as credentials. Unsupported private symlinks and non-directory ancestors reject before publication rather than masquerading as absent credentials.

After data availability, initialization exposes the private tree through a native `/run/startos-private-config` bind view, preserving shadow-group access without opening traversal of the data mount. Same-boot initialization reuses the matching view; main-filesystem teardown strictly releases only its own view before closing the mapper. The shared file-copy owner skips identical source/destination inodes, including shadow paths referring to the same backing file. Legacy replacement is a separate retryable step after durable compatible EFI activation and runtime-view availability. The activation owner still owns obsolete public extent reclamation, backing-reference pruning and interruption/reboot reconciliation. These file primitives do not establish active protection or complete initial enablement; the complete generator and activation owner must compose them before protected boot is enabled.

Public reference metadata is neutral in fresh and resumed projections; encrypted backings retain credential attributes. Temporary staging/replacement paths must not collide with configuration entries, including native-byte and maximum-length filenames. Legacy replacement rejects redirected parents and resumes from the durable projected generation after interruption, with the raw mount and path writers exclusively owned.

`util::io::{read_secret_file,write_secret_file}` avoid Tokio file buffers through native blocking I/O with fixed zeroizing read allocations and owned zeroizing write bytes. Callers retain responsibility for original values, opaque source-reader/serializer storage and process-memory protection; these file operations do not erase those other owners' copies.

Boot uses immutable verified rootfs and overlay images with a temporary writable root layer. `/media/startos/config/overlay` exposes a separate editable view of the overlay squashfs with its own RAM-backed upper layer; editing that view must not mutate an active lower layer of the running root.

The running root layers the immutable configuration over the immutable public image, with a separate RAM upper for runtime writes. The configuration-only working mount lives inside the running root's config bind. `BootConfiguration::working_upper` retains its raw upper path for snapshot preparation; edits enter through the working mount, not the raw upper. All composed mounts end before verified lower mappings close.

OS operations commit after editing; administrators may make manual edits and explicitly commit. Writers must quiesce while commit captures the working view. A commit publishes a complete, durable signed generation before attempting to remove older generations. Cleanup failure does not undo successful publication. Unpublished staging generations are not boot candidates.

`start_core::os_overlay` prepares, signs and durably publishes complete generations using the native SquashFS writer. Working-view export shares the filesystem merger used for OCI layers; RAM-upper deletion removes a configuration override, while untouched raw-lower whiteouts and opaque markers retain their rootfs deletion semantics. Working mounts disable `index`, `metacopy` and `redirect_dir`. `VerityImage::open` returns an owned `VerityMapping` after reading every block, closes failed initial mappings, and rejects later corruption with I/O errors. Native creation, full reads, mounting and explicit guarded teardown finish under retained task ownership when a caller cancels; an abandoned successful result is reclaimed by its guard. This guarantee requires an active async runtime, not survival of process death. Each fresh mapper name stays reserved until setup and cleanup finish; path disappearance alone is not completion. FDE mount guards reject busy references instead of lazily detaching during explicit or drop teardown; other mounts retain their existing lazy/strict policy. Explicit close retains its name until native removal succeeds. Abandoned or failed mapping guards request native deferred removal, retaining kernel integrity protection until the last reference ends. An error does not release the caller's reservations or establish completed cleanup.

Boot chooses the newest complete, signature-valid, content-verified generation by timestamp. This is not anti-rollback protection: an attacker can delete newer generations. No signed generation counter or TPM-backed freshness floor is required.

## Existing installations

Migration replaces the legacy default-password keyslots with the admin password and replaces header backups under `/media/startos/config/luks`. It does not rotate volume keys or re-encrypt already encrypted volumes. Interrupted migration must remain recoverable across both data volumes; enrollment cannot complete while the default credential remains accepted.

`DefaultKeyslots` records original DEFAULT authority separately from administrator slots. `LuksPool::retire_default_slots` requires durable compatible EFI activation and verified current administrator authority; password changes may replace the first installation's targets before retirement finishes. Reused slot IDs do not authorize deleting replacement administrator or manual keys. Native retirement preserves unrelated current slots and regenerates both header backups without volume-key rotation. The enable coordinator persists this authority before initial slot mutation; complete enable/commit still must supply the durable compatible EFI activation gate. Native slot operations alone do not establish protection.

`fde::enable` owns optional `private.fdeEnrollment.administrator` intent. `Installing` persists an initial administrator plan, original DEFAULT identity and current account hash before any slot mutation. It retains boot-lifetime keys, installs both administrator targets and recovery headers, then atomically commits `Installed` original DEFAULT authority with `private.luksCredentials::Stable`. Initial setup never relabels DEFAULT as administrator authority or retires it. A changed account password aborts incomplete targets before replanning against the same original DEFAULT record; an installed administrator uses the existing account-password owner and its shadow completion step. Enrollment retries synchronize the committed password into active and saved shadow files even when slot retirement fails, and repair a prior shadow-write failure on stable retry. These states record pending administrator setup, not EFI publication or active protection. Native allocation, installation, abort and metadata checks share the password-change primitives while retaining distinct authority types and unchanged legacy password-plan storage.

Initialization and daemon restart recover pending keys after secret-memory admission, before typed normalization and migrations. The shared recovery owner uses retained keys first; absent keys may be captured from persisted DEFAULT authority on an ordinary pending-enable boot. Protected boots reject this path without retained unlock keys. Recovery takes no prior plaintext password, preserving new-password-only resets after pending enablement loses its volatile cache. This does not activate protected boot or implement cancellation; EFI publication, DEFAULT retirement and whole-caller reservations remain the activation owner's obligations.

The account owner stores optional `private.luksCredentials` with `Stable`, `Installing` and `Retiring` stages. `Installing` persists the target hash and native plan before keyslot changes. After both target slots verify, one durable PatchDB mutation commits the account hash and `Retiring` authority; successful retirement publishes `Stable`. A different request aborts an uncommitted installation before replanning. A committed retirement can finish with retained volume keys before another password is installed, without the prior plaintext. These stages describe credential intent, not observed active FDE.

The password RPC serializes slot, account and shadow changes with `RpcContext::password_changes` and retains the operation when its requester disconnects. Login shadow repair shares that owner and ignores a password superseded after login validation. An existing shadow overlay takes the ordinary-login fast path without credential-lock acquisition or a second password hash check. Accepted missing-shadow repair is retained through requester cancellation. After account commit, shadow synchronization uses the committed password even if slot retirement fails; the original operation failure takes precedence over a secondary shadow failure. Account commits update only password/credential fields, preserving concurrent identity updates. With no LUKS credential record, ordinary password changes retain their existing disk behavior. Protected unlock caches keys before constructing the ordinary server context; initial enablement populates administrator authority while retaining original DEFAULT authority through compatible activation.

`start_core::disk::fde::LuksPool::plan_password_change` reads identity-bound intent without mutating either LV. The account owner persists this plan and the target password hash before installation, retaining exclusive keyslot ownership until completion or abort. Installation verifies both target slots before the owner commits the new account hash and administrator-slot authority. Retirement follows that commit and resumes using the new password alone. Abort precedes account commit and preserves the complete base inventory, including unrelated manual keys. A different target requires successful abort and a fresh plan. Header replacement shares the normal disk-import owner. Unencrypted `_UNENC` pools require a separate encryption migration before this API applies.

An authorized password reset requires only the new password, not the old plaintext. Password unlock may capture volume keys for the caller's protected volatile OS-boot-lifetime cache, surviving daemon restarts but not reboot. These keys never enter persistent storage, backups, PatchDB, bootstrap state, logs or an additional management keyslot. The boot owner protects their handling from swap, core dumps and diagnostics.

`LuksPool::cache_unlock_keys` and `cached_unlock_keys` use the initial-user-namespace root user keyring, pinned by the kernel's user-namespace register. Kernel `user` payloads are unswappable and do not expire unless explicitly timed out or removed. Volume UUID and mapper identity bind each payload; partial or absent pairs do not yield keys. Native key metadata must identify a root-owned `user` key before read or update. Root user-ring and payload permissions exclude possessor, group and other access; this hardens the whole root user keyring, not merely the FDE entries. Native process-keyring links supply creation-time possession in private sessions and end with their process; the user ring retains the payloads independently. Restored bytes reuse the existing zeroizing `VolumeKeys` and keyslot APIs for LUKS1 and LUKS2, without a serialized cache format, daemon or extra keyslot. Caller protection of transient userspace copies and boot/unlock lifecycle integration remain required. The account password path shares process-secret protection with initramfs handling and validates its temporary credential filesystem before loading keys. This does not establish the complete daemon/boot lifecycle.

Retiring obsolete header copies relies on Btrfs discard and storage returning zeroes for deallocated blocks, specifically NVMe DLFEAT=001b. This assumption is not a cryptographic secure-erasure guarantee and cannot revoke header copies previously taken off the device. Header backups copied into backupfs retain that filesystem's password-encrypted protection.
