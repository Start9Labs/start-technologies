# Full-disk encryption contract

FDE is opt-in and targets UEFI systems with TPM 2.0 and Secure Boot. The immutable OS image and the encrypted data drive remain separate. The admin password independently unlocks the data volumes; TPM availability is not a prerequisite for recovering data with that password.

Enabling FDE owns the enrollment workflow; enrollment is not a separate prerequisite delegated to the user. Before confirmation, the enable UI prominently warns: “After every restart, your server and its services will remain offline until you unlock it with your password.” Enabling requires explicit acknowledgment of that consequence. The restricted password-entry page is the pre-unlock access surface, not an available normal server or service. Persisted enable intent, pending enrollment and observed active FDE must remain distinguishable; requesting enrollment cannot be reported as completed protection.

## Bootstrap identity

Boot attestation gates the private TLS identity used by the password-entry page and the network credentials needed to reach it. It does not release a data-volume password or data-decryption key. A failed attestation cannot silently enroll changed boot state or fall back to presenting the valid unlock identity.

The measured execution chain must authenticate the kernel, initramfs, effective command line, rootfs and persistent overlay before bootstrap credentials are released. The authorized policy must bind the verified loader path: an alternate trusted kernel running an unsigned initramfs must not gain access by replaying public UKI or filesystem measurement events. Filesystem contents must remain integrity-protected after verification. Merely authenticating a filename or measuring a mutable directory does not satisfy this contract.

`start_core::fde::bootstrap` authenticates and encrypts the bootstrap payload. `start_core::fde::tpm` seals its random encryption key to a P-256-authorized policy over SHA-256 PCRs 0, 2, 4, 7, 11, 12, 13, 14 and 15, restricted to `Unseal`. The policy reference binds the canonical bank/register selection; an authorization for a weaker selection cannot unlock the object. Firmware and option ROM measurements are pinned alongside Secure Boot and shim MOK policy. PCR 4 binds the loaded application sequence; PCR 11 belongs to the UKI measurement chain; PCR 15 binds the verified rootfs and overlay. Unexpected firmware or trust-policy changes require trusted re-enrollment, not automatic resealing. The policy-signing private key belongs on the encrypted data drive. The TPM policy authorization and the overlay manifest signature are distinct messages. TPM helpers must not inherit TSS diagnostic verbosity: debug output includes session keys. The shared command boundary clears `TSS2_LOG`, retaining the library's default diagnostics.

`fde::tpm::MeasurementProfile` pairs public expected PCR values with their authorization. Reuse as authorization inputs requires signature verification and recomputation of the TPM policy digest from those values. A valid signature on a policy digest alone does not authenticate adjacent measurement metadata. Observed post-phase PCR values are not future pre-phase predictions.

`start_core::fde::credentials` carries encrypted TLS material and NetworkManager profiles without a data-unlock password. Local certificate issuance shares the normal server's intermediate-only issuer and certificate cache; the bootstrap issuer excludes the root CA private key. ACME snapshots contain the selected providers' settings, accounts and cached identities, and reuse normal issuance and challenge handling. Leaf identities share the normal certificate-chain type and TLS configuration builder. NetworkManager keyfile discovery is shared with the existing saved-profile owner. Bootstrap keyfiles are materialized with private permissions beneath `/run`, then removed individually during handoff; saved data-drive profiles remain authoritative.

`net::net_controller::plan_host_exposure` owns exposure decisions for normal and standalone consumers. Standalone interface discovery and vhost listeners accept saved input, interface watches and injected TLS sources without constructing private-database state.

These primitives alone do not establish the measured boot chain or enable FDE on a server.

## UKI construction

`build/lib/scripts/fde-build-uki` embeds the kernel, initramfs, effective command line and OS release in a native-architecture UKI, signed using the enrolled RSA Secure Boot identity. That private key belongs on the encrypted data drive and is distinct from the P-256 policy authority. PCR11 prediction uses the final image's actual virtual section contents through systemd tooling; Authenticode signing timestamps do not select boot state.

The authorized application sequence is firmware → shim → UKI, without GRUB or another command interpreter. Shim directly loads the machine-signed UKI from its second-stage EFI path. The supported measurement profile includes the whole UKI, not a separately measured embedded kernel. Extra applications, returned-image fallback paths and unsupported firmware measurement behavior fail closed; they are not learned as replacement policy. Vendor and Microsoft firmware trust may remain enrolled. The MOK certificate must permit image signing; a module-only certificate is insufficient.

PCR4/PCR7 prediction must validate the current event-log replay against live PCRs and preserve the trusted firmware/shim prefix. The future UKI and its actual enrolled authority determine the replacement events. The enable workflow starts enrollment from a trusted running installation or recovery environment; public-log consistency alone does not establish that trust. PCR14 binds MOK policy, including unused allowlist and denylist entries.

`start_core::fde::loader` captures a caller-authenticated current chain, including legacy GRUB and kernel artifacts, and retains only the firmware/shim prefix. Future predictions pair the exact UKI application digest with its enrolled MOK authority event. The validated legacy tail is not a future authorization. Baselines belong in the encrypted database, never public boot configuration.

The helper creates a UKI and a `.pcr11` companion in a private staging generation on a hard-link-capable filesystem. The companion contains 64 lowercase hexadecimal digits and a newline, describing SHA-256 PCR11 before any initrd phase events. The pair is not independently atomic: the enclosing complete generation owns publication. Existing output files are not replaced on errors.

Activation makes the compatible rootfs, overlay and policy generation durable before replacing the complete EFI image on the ESP. Old dependencies remain until activation is durable. The old UKI may select only overlays with a compatible rootfs and an authorization for that boot/filesystem combination. FAT replacement does not guarantee boot availability across a power cut; signature and TPM failures remain fail-closed. The supported profile excludes external stub inputs by requiring empty PCRs 12 and 13 when authorizing. This excludes external parameters, credentials, configuration/system extensions, nondefault UKI profiles and addons; public boot metadata cannot authorize them.

## Boot selection

`fde::boot::Descriptor` pins one rootfs filename and the manifest/policy verification keys inside the signed initramfs. Unsigned configuration cannot replace those keys or choose a non-FDE boot mode. Complete generations live under `config/fde/generations`; their public policy files remain outside the hashed configuration image to avoid a filesystem-policy hash cycle.

Generation metadata files and leaf directories require passive type admission before opening or listing. Symlinks and special files are not metadata providers. Policy selection, store enumeration, publication and pruning share the directory owner; metadata/image reads share the regular-file owner. Callers keep source paths stable throughout admission and verification; these checks are not path-lifetime protection.

Selection reuses `os_overlay::verified_generations` ordering and admits the newest candidate whose authenticated policy matches the observed boot plus its anticipated filesystem event. A newer signed filesystem without a matching boot authorization does not displace an older compatible generation. `Descriptor::mount` opens and fully reads both signed verity mappings and mounts them as read-only SquashFS. `MountedGeneration::measure` checks the live boot again before extending PCR15. Mount guards remove mappings after successful unmount, or transfer both resources to the boot owner for handoff. Selection alone cannot release credentials; dependent mounts must end before their mappings close.

`startbox start-fde-prepare` takes the OS-volume mount and target root mountpoint. It reads the descriptor from the authenticated FDE initramfs, not disk configuration; guarded release composes the running and working roots before measuring the protected filesystems and decrypting the bootstrap snapshot. Its caller must terminate on error without ordinary-boot fallback or an interactive shell. The signed FDE mount route waits up to 30 seconds for the local kernel TPM resource-manager device `/dev/tpmrm0`, then binds that device TCTI to the preparation command alone. Device existence is sufficient; TPM nodes need not have udev database entries. Readiness failure terminates before preparation. Other TPM consumers retain their transport selection. The normal initramfs does not invoke it.

The preparation helper excludes active swap and piped core handlers, disables its own dumpability and inherits a zero core limit into TPM tools. These conditions must remain stable until release finishes. Runtime identities and TPM workspaces use private `noswap` tmpfs mounts; the private handoff remains RAM-only after helper exit. This initramfs protection does not establish the separate OS-boot-lifetime volume-key cache or protect later daemon handling by itself.

`fde-harden-initramfs.mjs` delegates to the shared `fde-initramfs-control.mjs` library and transforms the reviewed initramfs-tools 0.148.4 control plane in a caller-owned private tree. It rejects changed or unknown providers/configuration before mutation. Failure handling never returns to boot, including when reboot fails; break requests and alternate-init fallback cannot open a shell. The transform fixes the FDE boot route and removes resume, live boot, keymap execution, runtime parameter sourcing and automatic `/usr` mounts. Ordinary generated images are not transformed.

Pre-verification udev must not invoke shells or select external command names from event properties. The same transform pins reviewed udev 257.13 rules and optional dmsetup/Btrfs rules, removes environment-selected removal commands and shell-based `ibmveth` naming, and preserves storage discovery, fixed helpers and other interface naming. Unknown or changed rules, rules in alternate directories and noncanonical library aliases reject before mutation. Directory ancestors cannot be symlinks; the generated `/lib` alias must point to `usr/lib`.

The supported FDE initramfs profile excludes effective module `install`/`remove` commands. The transform queries both native `modprobe --showconfig` and libkmod's public configuration-iterator API for the included kernel and explicit configuration directories, including `modules.softdep`/`modules.weakdep`. Both views matter: the CLI may embed libkmod while udev loads the shared library. Copied CLI/shared-library bytes must match their trusted native query providers, and provider links must stay within the candidate. The Python 3 standard-library bridge loads the admitted source library, never candidate code, and does not probe or load modules. Platform precedence, options, blacklists and dependency parsing remain native; no parallel parser rewrites configuration. Inherited command/log overrides, parser errors and executable commands cannot bypass admission. Source providers and candidate files remain stable through hardening. This file-identity check does not establish the remaining loader/helper closure.

`fde-initramfs-tools-hook` belongs only in a private generation's hook configuration, never the ordinary initramfs hooks. The native module collector requests the kernel TPM driver family (`=drivers/char/tpm`); native dependency/firmware handling supplies it and udev modalias handling selects the driver. Native `copy_exec` copies the installed product binary, verity helper, TPM multicall binary and libraries. The TPM package owns its alias inventory; aliases must resolve to that binary. The native-architecture device-TCTI package supplies its dynamically loaded provider explicitly. The signed mount route owns runtime transport selection; helper/plugin closure remains the generation owner's obligation. The generation owner must admit stable providers and transport, and discard the complete candidate on hook failure.

`prepareNativeHooks` in `fde-initramfs-hooks.mjs` admits reviewed native build hooks into a fresh private directory before their prerequisite methods or bodies run. Unknown, changed, missing required and non-executable hook contexts reject before publication. Credential, resume, keymap and FUSE hooks are excluded from this pre-unlock profile. Optional Intel/AMD microcode hooks retain native firmware selection and archive generation with admitted default configuration; their private copies fail on missing helpers, unsupported kernels or failed generation/append instead of reporting success. AMD's package timestamp remains integer metadata. The private BusyBox hook retains native applet selection and emits relative symlink aliases. The private klibc hook retains native command exclusions and existing-command precedence, copies regular helpers at their source paths through native `copy_file`, and emits relative command aliases. Copy failures terminate the private hook. The returned handle binds provider admission to native metadata queries in the admitted source namespace. Their private query bodies derive directly from the pinned native selector/normalization code; source helpers supply applet inventory, not a second decision list. Native installation retains existing-command precedence. Original providers are not modified. Source helpers/configuration must remain stable and hooks execute in that admitted source namespace. Build-hook admission is not the complete early writer set. `admitInitramfsSources` composes original runtime-provider admission with configuration-source admission before the producer's first source operation. It shares generated configuration contexts with the control-plane owner and native `hook-functions` admission with the producer. Main, shared/private fragment and package hook configurations must have reviewed contexts; this obligation includes masked fragments in either source tree. Native selection and precedence remain unchanged. Generated `ORDER` data is never an original executable source. The required `FDE_ADMIT_SOURCES` stage uses `fde-admit-initramfs-sources.mjs` to check the actual namespace and private configuration directory without another tree or override/ordering implementation. Source providers remain stable through consumption. Helpers, firmware and other inputs still require complete generation-owner admission.

The handle's `admitProviders` delegates to `admitCopiedProviders` in `fde-initramfs-providers.mjs` and passively compares copied regular `/usr` files and permission modes with their canonical public source paths using the source `cmp`. Canonical relative symlinks must stay within the copied public tree and match a native provider slot or the source namespace's own alias semantics. Absolute and leave-and-reenter links are rejected even when they resolve inside the build directory: extraction changes that root. This pass runs before private control-plane rewriting, with source, hooks and candidate stable; it executes source metadata queries, never candidate code. After byte and alias admission, `admitNativeDependencies` uses source `readelf` metadata for ELF interpreter paths and the pinned native `copy_exec` implementation for required dependency paths. Declared source ELF dependencies must resolve successfully through source `ldd` before copying: native `copy_exec` discards its failure status and unresolved-library diagnostics. Files without declared dynamic dependencies, including static and klibc providers, retain their native interpreter/copy handling. Its fresh private reference tree retains native dependency selection, nonoptimized-library handling and copy deduplication; reference bytes confer no authority. Required files and interpreter aliases must exist in the already-admitted candidate namespace. Included firmware shares this same-path byte/mode/alias admission; it is not interpreted as userspace ELF. Firmware selection, optional source absence and collector-copy errors are separate from included-file integrity. Reference storage is removed on success and failure. Source metadata, comparison and collection commands share one environment boundary excluding inherited overrides. Kernel modules, generated configuration, exact loader/cache behavior, runtime plugins and EARLY inputs retain separate admission obligations. This provider pass alone does not authorize signing or activation.

`fde-initramfs-linker.mjs::admitLinkerCache` requires completed provider identity admission. It reuses the reviewed producer's configuration-copy instruction for source and candidate, comparing selected regular configuration files and modes. This reviewed profile excludes `ld.so.preload`. Source `ldconfig` regenerates the expected subset cache in private storage containing cloned admitted providers and root aliases; candidate code is neither executed nor loaded. The candidate cache must be regular and match the generated bytes. Private storage is removed on success and failure, and candidate contents/layout remain unchanged. This admits configuration/cache integrity, not complete RPATH, NSS or plugin resolution.

`fde-initramfs-modules.mjs::admitKernelModules` admits one canonical regular-file module tree matching the source kernel version. Packaged `modules.order`, `modules.builtin` and `modules.builtin.modinfo` are required source inputs. Native source `depmod` regenerates subset indexes in fresh private storage from corresponding authenticated source files, never candidate module bytes. Every generated index must match; remaining candidate files require same-path source bytes and permissions. The shared `admitModuleConfiguration` owner admits copied query providers and checks effective configuration through both native CLI and shared libkmod before returning its query/configuration paths. Source `modinfo` identifies modules; source `modprobe --show-depends` uses those effective paths and requires its native dependency paths in the admitted set. This dry-run query preserves soft dependencies: libkmod's `--ignore-install` would suppress them as well as install commands. Install/remove commands reject before dependency lookup. Native diagnostics reject. Private references are removed on success and failure. Canonical tree traversal, single-kernel selection and regular-file comparison share their production owners with control/provider admission. The existing source-library bridge also reads effective weak dependencies through libkmod's public API. Each available returned path must belong to the admitted set; querying every copied subject covers transitive requirements without a second graph walker. Native unavailable-optional semantics remain unchanged. The bridge shares its source-library bindings and context lifetime with configuration-command admission, and never loads candidate libraries or inserts modules. The pinned source hook-functions collector also produces an independent private module/firmware requirement tree for copied subjects. Native diagnostics reject even when ignored firmware-copy failures leave a successful exit status. Every collected public path must bind the corresponding candidate/source path; selected firmware requires source bytes/modes, while admitted module identity is reused. Reference aliases share their copying owner with linker-cache admission, and unexpected namespaces reject. This preserves native optional source absence rather than requiring every declared firmware name. Native `add_builtin_firmware` also collects source built-in requirements into that reference, sharing candidate/source identity and presence checks. Its private adaptation makes selected-copy failures terminal without changing native selection or optional absence; the known optional-missing warning is omitted, and other diagnostics reject. Configured alias/request coverage and complete generator admission retain separate obligations; this is not complete module-loading or boot authority.

`fde-initramfs-producer.mjs` adapts only the reviewed installed `mkinitramfs` and `hook-functions` 0.148.4 sources, without patching system providers. A private adaptation is necessary: native hooks run before generated `ORDER` files. Its separate source-admission and completed-tree preparation stages protect different execution boundaries. It runs native build hooks only from the caller's admitted `FDE_NATIVE_HOOKS` directory; `CONFDIR` and its additional hooks also belong to the private generation. Native dependency ordering is unchanged. It adds a required preparation program after ordering, dependency generation and DSDT copying, before native packaging. That program owns the complete closure audit and hardening, including the native early stream. Native ordering, microcode handling, file-list construction and CPIO/compression routines remain the producers; standard `tee`/copy capture their streams with native failure propagation. The profile permits gzip/pigz and rejects appended native overlays.

The generation owner supplies stable runtime providers, a trusted preparation program and a private capture directory outside the generated tree. Captures are create-only, mode 0600, and remain private through verification/consumption. The owner excludes other writers and discards the complete candidate on failure. `capturedStreams` owns capture filenames and prefix ordering. This adaptation is not a complete generation command or closure audit; its packaging tests do not establish full `mkinitramfs`, kernel or firmware execution.

`Descriptor::mount_source` reuses signed-generation admission independently of live PCRs and boot-policy files. Building after PCR15 measurement requires public filesystem authority, not permission to unseal bootstrap identities. It opens the selected signed public image through `VerifiedGeneration::mount_rootfs`, shared with boot mounting, without mounting configuration. `fde::source::BuildSource` layers that protected public rootfs over its embedded public container-runtime image, both read-only. Runtime fallback supplies the packaged Node and its absolute builtin/library paths; running, working and configuration overrides cannot replace source providers. The runtime image must resolve inside the verified public filesystem. A shared `VerifiedMounts` lifetime owner unwinds dependent mounts before their verified lower owner, including failed composition; source and running-root flows remain separate. The lower-only `OverlayFs::read_only` view has no writable upper/work directories and a distinct mount identity. Source admission retains signature selection and native public/runtime/overlay setup when its waiter is cancelled. An abandoned completed source unwinds its dependent mounts and mapping. This requires an active async runtime; the caller reserves the source mountpoints through setup and cleanup, not merely until a path disappears. The source view alone does not execute a generator.

`BuildSource::run_script` consumes that owner and returns script stdout after execution and source teardown. Its entry point is a regular file resolving under the verified view's `/usr`, outside writable scratch. Runtime-image and entry-point containment share one path owner. Scratch and proc mountpoints cannot be aliases that escape or shadow public providers. Private `noswap` tmpfs mounts supply `/dev`, `/run`, `/tmp` and `/var/tmp`; the device view exposes only null, zero and kernel entropy devices. Native util-linux creates private mount/PID/network/IPC/UTS namespaces and proc before running the packaged Node in the source root with a cleared environment. No running/working configuration, data volume, host network or host device tree is imported. Script arguments and stdin are data interpreted by the admitted script, not alternate entry points. Normal success and command failure unwind scratch before public mappings; caller cancellation retains the entire operation while the async runtime remains active. Verity and source jobs share this retained-operation primitive. An owned operation's panic resumes with its original payload rather than becoming a filesystem error. This is not process-death recovery or a complete generator: the orchestration script must still compose source/closure admission, private hooks, native production, archive verification and consumption before any signing/publication.

`runNativeProducer` in `fde-initramfs-producer.mjs` runs admitted native production in util-linux PID and private mount namespaces. Ordinary producer exit ends every descendant, including detached writers, before success or producer-exit rejection reaches the archive owner. Source providers and the private workspace remain owned throughout the call, and the source root is a mountpoint. Launcher death is an error, not a completed-production proof. This primitive does not provide source-root setup, process-death recovery or the complete generator caller.

`withPrivateInitramfs` in `fde-initramfs-generation.mjs` owns a fresh private archive/capture workspace through production, native-stream verification and completed consumption. It passes capture paths only to the trusted producer and removes the workspace on production, verification or consumption failure as well as success. The producer must admit sources and executable closure before capturing, and join all writers before returning; the consumer completes archive use before returning. This lifetime owner does not supply source authorization, closure auditing or publication.

`fde-initramfs-archive.mjs` checks provenance of a private generated gzip initramfs: native-generated uncompressed prefixes match byte-for-byte, and the complete decompressed main stream matches its native-generated CPIO source. The producer must capture those sources after its executable-closure audit and exclude concurrent writes through consumption. Public proof files cannot authorize an image. Native extraction alone is insufficient: `unmkinitramfs` 0.148.4 does not inspect multiple compressed archives, and extraction can omit a later archive the kernel consumes. This provenance check delegates decompression to zlib and requires complete compressed-input consumption, including bytes following zero padding; it neither parses CPIO nor establishes arbitrary archive validity.

The build-time helpers support the Node 20.19 runtime already present in the public container-runtime image. Reuse requires its shared libraries and externalized `/usr/share/nodejs` builtin data in the admitted source namespace. The library/CLI split preserves symlink invocation without runtime-specific main-module detection. This does not install Node in the boot initramfs or establish the complete on-device builder namespace.

These helpers are not a complete image builder or executable-closure audit. Full generation ownership, helper binaries, matching runtime dependencies/plugins and closure/archive integration remain prerequisites before signing or activating an FDE image.

## Persistent overlay

The persistent overlay is an independently signed squashfs. Boot uses immutable verified rootfs and overlay images with a temporary writable root layer. `/media/startos/config/overlay` exposes a separate editable view of the overlay squashfs with its own RAM-backed upper layer; editing that view must not mutate an active lower layer of the running root.

The running root layers the immutable configuration over the immutable public image, with a separate RAM upper for runtime writes. The configuration-only working mount lives inside the running root's config bind. `BootHandoff::working_upper` records its raw upper path for snapshot preparation. All composed mounts end before verified lower mappings close.

OS operations commit after editing; administrators may make manual edits and explicitly commit. Writers must quiesce while commit captures the working view. A commit publishes a complete, durable signed generation before attempting to remove older generations. Cleanup failure does not undo successful publication. Unpublished staging generations are not boot candidates.

`start_core::os_overlay` prepares, signs and durably publishes complete generations using the native SquashFS writer. Working-view export shares the filesystem merger used for OCI layers; RAM-upper deletion removes a configuration override, while untouched raw-lower whiteouts and opaque markers retain their rootfs deletion semantics. Working mounts disable `index`, `metacopy` and `redirect_dir`. `VerityImage::open` returns an owned `VerityMapping` after reading every block, closes failed initial mappings, and rejects later corruption with I/O errors. Native creation, full reads, mounting and explicit guarded teardown finish under retained task ownership when a caller cancels; an abandoned successful result is reclaimed by its guard. This guarantee requires an active async runtime, not survival of process death. Each fresh mapper name stays reserved until setup and cleanup finish; path disappearance alone is not completion. FDE mount guards reject busy references instead of lazily detaching during explicit or drop teardown; ordinary mount policy is unchanged. Explicit close retains its name until native removal succeeds. Abandoned or failed mapping guards request native deferred removal, retaining kernel integrity protection until the last reference ends. An error does not release the caller's reservations or establish completed cleanup.

Boot chooses the newest complete, signature-valid, content-verified generation by timestamp. This is not anti-rollback protection: an attacker can delete newer generations. No signed generation counter or TPM-backed freshness floor is required.

## Existing installations

Migration replaces the legacy default-password keyslots with the admin password and replaces header backups under `/media/startos/config/luks`. It does not rotate volume keys or re-encrypt already encrypted volumes. Interrupted migration must remain recoverable across both data volumes; enrollment cannot complete while the default credential remains accepted.

`start_core::disk::fde::LuksPool::plan_password_change` reads identity-bound intent without mutating either LV. The account owner persists this plan and the target password hash before installation, retaining exclusive keyslot ownership until completion or abort. Installation verifies both target slots before the owner commits the new account hash and administrator-slot authority. Retirement follows that commit and resumes using the new password alone. Abort precedes account commit and preserves the complete base inventory, including unrelated manual keys. A different target requires successful abort and a fresh plan. Header replacement shares the normal disk-import owner. Unencrypted `_UNENC` pools require a separate encryption migration before this API applies.

An authorized password reset requires only the new password, not the old plaintext. Password unlock may capture volume keys for the caller's protected volatile OS-boot-lifetime cache, surviving daemon restarts but not reboot. These keys never enter persistent storage, backups, PatchDB, bootstrap state, logs or an additional management keyslot. The boot owner protects their handling from swap, core dumps and diagnostics.

Retiring obsolete header copies relies on Btrfs discard and storage returning zeroes for deallocated blocks, specifically NVMe DLFEAT=001b. This assumption is not a cryptographic secure-erasure guarantee and cannot revoke header copies previously taken off the device. Header backups copied into backupfs retain that filesystem's password-encrypted protection.
